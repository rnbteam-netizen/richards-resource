## Long-term data behavior
- **Refresh policy**: None — resources are stable reference data; user data is user-entered only, no scheduled refresh.
- **Growth**: One quit profile per category (upserted); urge/boundary logs append, newest first, capped display at 100. Points events append (values set server-side; touches and field counts are stored as single batched rows); getState sums ALL point events into per-tab totals — no cap and no window — and returns the 30 most recent events plus recent day marks.
- **Ordering**: Logs newest first; tabs fixed order: Home, Alcohol, Smoking, Gambling, Drugs, Codependency, Food, Screens, Feeling Unwell?, Help & Resources.
- **Time semantics**: Quit date stored as YYYY-MM-DD date string (user's local day); streak and money saved computed from calendar days elapsed; log timestamps are creation instants rendered viewer-local.
